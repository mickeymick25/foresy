- **UC-4** : signup → login JWT → company onboarding (pivots) → missions ×2 (pivots user_missions/mission_companies) → CRA → entries ×2 liées aux missions → totaux serveur (1,0 j / 65 000 cents) → submit → lock → **commit Git Ledger réel** (hash 40 hex, message contractuel `CRA locked — cra:<uuid>`) → double lock 409 sans delta de commits → protection entry 409 → état final GET cohérent.

| **UC-5** — multi-missions / pivots | **2 nouvelles specs** (`spec/system/cra_multi_missions_system_spec.rb`) | Deux propriétés de composition réellement non couvertes (voir ci-dessous). |

### Cycle D2 (pas de RED — propriétés fonctionnelles, caractérisation)

Aucun bug révélé en D2 : les deux propriétés fonctionnent **grâce au fix D1** (avant, `mission_id` étant perdu, le garde duplicate était inerté et une mission inexistante était ignorée silencieusement). Les specs verrouillent ces propriétés au niveau système.
